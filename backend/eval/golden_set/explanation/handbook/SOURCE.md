## `chunks.json` — how `SectionChunker` actually split it

`SectionChunker(min_tokens=100, max_tokens=500)` produces **7 chunks**: a short preamble plus one chunk per numbered section. No collisions — every label appears in a single run, so every ordinal is `#0`.

"Tokens" below is `count_words` (whitespace-split word count), the same approximation the chunker uses for its budget.

| chunk ID                               | tokens |
| -------------------------------------- | -----: |
| `_preamble#0`                          |    102 |
| `1. Travel#0`                          |    373 |
| `2. Lodging#0`                         |     79 |
| `3. Meals#0`                           |    161 |
| `4. Tipping Guide#0`                   |    200 |
| `5. Non-Reimbursable Expenses#0`       |    169 |
| `6. Expense Reimbursement Timelines#0` |    375 |

`2. Lodging#0` is 79 tokens, under `min_tokens=100`: the section is a single
short paragraph, and the chunker only merges an undersized tail into a _previous_
chunk of the same section, so a lone short section is emitted as-is. Not
degenerate, just small; flagged here as the one chunk a future `min_tokens`
tweak would move.

The handbook is not reshaped to coax nicer chunks — cases work from whatever the
real pipeline produces.
